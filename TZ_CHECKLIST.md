# Проверка соответствия ТЗ

## Реализовано

- Django backend + PostgreSQL; параметры БД/хранилища вынесены в settings/.env.
- React + Redux + React Router SPA.
- Регистрация: логин 4–20, латиница/цифры, первый символ буква; email; полное имя; пароль минимум 6, заглавная, цифра, спецсимвол.
- Сессионная аутентификация, logout, CSRF-защита изменяющих запросов.
- Навигация зависит от статуса аутентификации.
- Админ: список пользователей, регистрационные данные без пароля, признак администратора, удаление/изменение прав, количество и объём файлов, переход к хранилищу.
- Обычный пользователь работает только со своим хранилищем; администратор — с любым выбранным хранилищем.
- Файлы: список, загрузка с комментарием, удаление, переименование, изменение комментария, скачивание, публичная UUID-ссылка.
- В списке файлов: имя, комментарий, размер, дата загрузки, дата последнего скачивания.
- На диске файлы сохраняются с уникальными UUID-именами в каталогах пользователей.
- Публичная ссылка обезличена и скачивает файл с исходным именем.
- Физический файл удаляется при удалении записи/пользователя.
- Логирование в консоль с датой/временем и уровнями.
- Vite production build обслуживается Django/WhiteNoise вместе с API одним сервером.
- Миграции создают структуру БД и запись initial admin; пароль берётся из ADMIN_INITIAL_PASSWORD.
- Добавлены backend-тесты ключевых прав доступа.
- README содержит структуру, запуск, сборку и production-развёртывание.

## Требует действий владельца проекта вне исходного кода

- Создать публичный GitHub-репозиторий и загрузить историю/актуальную версию проекта.
- Развернуть приложение на reg.ru и указать публичную ссылку при сдаче (либо согласовать развёртывание по запросу проверяющего).
- Перед production задать реальные SECRET_KEY, DB_PASSWORD, ADMIN_INITIAL_PASSWORD, ALLOWED_HOSTS и CSRF_TRUSTED_ORIGINS.
- Выполнить на реальном окружении PostgreSQL: `python manage.py migrate`, frontend build и smoke-test всех основных сценариев.
